# QA Plan (`ags-qa qa-plan`)

Generates a structured sprint, feature, or story QA plan using `.ags/templates/test-plan.md`, classifying stories by test type and mapping GDD formulas and edge cases to concrete verification obligations.

**Output:** `production/qa/qa-plan-[sprint-slug]-[date].md`

---

## Configuration Rules

- **`modes.workflow` + `workflow_overrides.system_overrides`**: Resolve **per system** as each GDD is read (`workflow_overrides.system_overrides.<stem>` where `<stem>` is the `design/gdd/<stem>.md` filename stem; `TR-[system]-NNN` is fallback alias only). Controls which GDD sections are mined in Phase 2.
- **`qa.level`** (distinct axis from `workflow`):
  - `minimal`: Generate a minimal smoke-only plan — omit `## Automated Tests Required`, blank the `Automated Test Required` column in Test Summary, and drop the test-file, manual evidence-doc, and smoke rows from Definition of Done (leaving acceptance-criteria verification only).
  - `standard`: Full plan per story type.
  - `full`: Full plan plus per-system coverage targets.

---

## Phase 1: Parse Scope & N=0 Guard

Determine scope from arguments (or prompt the user if omitted):
- **`sprint`**: Read the latest file in `production/sprints/` and extract referenced story paths. Use `production/sprint-status.yaml` as the primary story list if present, falling back to the sprint plan for metadata.
- **`feature: [system-name]`**: Search `production/epics/*/story-*.md` matching the system path/title and check `EPIC.md`.
- **`story: [path]`**: Validate path exists and load that story.
- **`full`**: All stories in `production/epics/**/story-*.md`.

If one story path among several is missing, log it as `MISSING` and continue.

**Mandatory N=0 Guard:** If the resolved scope yields **zero stories**, STOP immediately without writing a plan document. Emit **`NOT ASSESSED — no stories in scope`**, naming the searched scope and empty path, and route:
- Missing `production/sprints/` file -> `"Run ags-plan sprint to create a sprint plan."`
- Sprint plan exists with zero listed stories -> `"Run ags-plan stories [epic-slug] to populate stories."`
- `feature:` / `story:` / `full` matched nothing -> name the empty path pattern.

---

## Phase 2: Load Inputs (Targeted Extraction)

Count the in-scope story files (`N`) first, then extract only the needed fields (`## Acceptance Criteria`, `> **Type|Status|Estimate**`, `## Context|Dependencies`) rather than reading every story in full. Full-read individual stories only when implementation/engine notes govern testing or when `## Acceptance Criteria` is absent.

**Never treat an absent section as an absent story.** If a story has no `## Acceptance Criteria`, full-read that story and flag the missing testable criteria as a QA finding.

Load supporting context once:
1. `design/gdd/systems-index.md`
2. Each unique referenced GDD, reading sections per that system's workflow tier:
   - `full`: all 8 GDD sections
   - `standard`: **Acceptance Criteria**, **Edge Cases**, plus **Formulas** when the system defines numeric rules
   - `minimal`: **Acceptance Criteria** only
   - If `Edge Cases` is missing (when expected), note `"No Edge Cases section found — edge case coverage inferred from acceptance criteria only."`
3. `docs/architecture/control-manifest.md` (if present) for forbidden patterns tests must guard against.

If a story references no GDD, note the gap without blocking and classify from acceptance criteria alone.

---

## Phase 3: Classify Each Story

- If the story header already specifies `Type:`, **keep it as-is** (set at story creation).
- If `Type:` is missing, infer it from the acceptance criteria and flag in the report that it was inferred and must be declared explicitly before implementation:

| Story Type | Classification Indicators |
|---|---|
| **Logic** | Formulas, calculations, thresholds, state transitions, AI logic, validation, buff stacking, economy math |
| **Integration** | Multi-system interaction, signal/event propagation across boundaries, save/load round-trips, network sync, persistence |
| **Visual/Feel** | Animation, VFX, shaders, responsiveness, perceived timing, screen shake, particles, audio sync |
| **UI** | Menus, HUD, buttons, screens, dialogue boxes, inventory panels, tooltips |
| **Config/Data** | Balance tuning values, data files, or config only — no new code logic |

For mixed stories (e.g., Logic+Integration or Visual+UI), assign the higher-risk primary type (prefer `Integration` when ambiguous between Logic and Integration) and note the secondary type. Present the classification summary table before Phase 4.

---

## Phase 4: Generate Test Plan

Populate `.ags/templates/test-plan.md` using actual story titles, extracted GDD formulas/bounds, GDD edge cases, and acceptance criteria (no placeholder text):
1. Header (`Date`, `Generated by: ags-qa`, `Scope`, `Engine`, `Sprint File`)
2. `## Story Coverage Summary` table (blank automated column at `qa.level: minimal`)
3. `## Automated Tests Required` (omitted at `qa.level: minimal`; test paths `tests/[unit|integration]/[system]/[story-slug]_test.[ext]`, formula checks, zero/min, max/cap, null/dead-entity, and GDD edge cases)
4. `## Manual QA Checklist` (Visual/Feel and UI checks with `production/qa/evidence/` method, sign-off role `game-designer` / `art-ux-director` / `qa-lead`, and falsifiable benchmarks for any subjective wording)
5. `## Smoke Test Scope` (for `ags-qa smoke-check`)
6. `## Playtest Requirements` (`production/session-logs/playtest-[sprint]-[story-slug].md`)
7. `## Definition of Done — This Sprint` (adjusted for `qa.level`, referencing `ags-qa smoke-check` and `ags-verify`)

---

## Phase 5: Write Output & Session State

Present the plan (or summary if large), then confirm output actions per `modes.automation`:
1. Write `production/qa/qa-plan-[sprint-slug]-[date].md` (full generated document, never truncated).
2. Optionally back-fill `## QA Test Cases` (for Logic/Integration) or manual verification steps (for Visual/Feel and UI) into each in-scope story file before `## Test Evidence`.

Append to `production/session-state/active.md` (creating it if absent):

```markdown
<!-- QA-PLAN: [date] | System: [system/sprint identifier] | Plan written: production/qa/qa-plan-[identifier]-[date].md -->
```

Route next steps: share plan before sprint start, implement required tests before `ags-verify` story closure, and run `ags-qa smoke-check sprint` once sprint implementation completes.
