# Soak Test (`ags-qa soak-test`)

Generates a timed endurance-play observation protocol to catch slow memory leaks, frame-time drift, state accumulation bugs, fun fatigue, and content exhaustion. Humans run the actual play session.

**Output:** `production/qa/soak-test-[date]-[duration].md`

---

## 1. Parse Arguments & Context

- **Duration** (default `1h`): `30m` (single mechanic/scene), `1h` (standard leak check), `2h` (recommended full Polish soak), `4h` (long-session RPG/sim). Match duration to intended session length.
- **Focus** (default `all` for first pass; narrow modes reserved for targeted regression soaks): `memory`, `stability`, `balance`, `all`.

Read from `preflight` / project files:
- `engine.name` and `performance.*` budgets (`memory_ceiling_mb`, `target_framerate`, `frame_budget_ms` from `project.yaml` / `preflight`; mark unset budgets `"not set"`).
- `design/gdd/game-concept.md` (or `design/game-brief.md` at `minimal`) for intended session length and core loop.
- Latest `production/qa/playtests/*.md` (avoid re-logging known issues) and latest `production/qa/qa-plan-*.md`.

---

## 2. Observation Checkpoints

- **`30m`**: T+0, T+10, T+20, T+30
- **`1h`**: T+0, T+15, T+30, T+45, T+60
- **`2h`**: T+0, T+20, T+40, T+60, T+80, T+100, T+120
- **`4h`**: T+0, T+30, T+60, T+90, T+120, T+180, T+240

---

## 3. Unit-Agnostic Memory & Engine Monitoring

> **Record the exact unit the profiling tool displays at T+0; never convert or assume units.** Every growth threshold below uses ratios or deltas against this session's T+0 baseline (or monotonic trend / orphan-node floor) rather than unverified API unit claims. (`Performance.get_monitor` return units are `NOT SOURCEABLE` in `docs/engine-reference/`.)

- **Godot 4**: Open Debugger -> Monitors tab. Record `Memory -> Static Memory` (unit as displayed), `Object Count -> Objects`, and `Orphan Nodes`.
  - **Alert**: Static Memory growth **> 20%** from T+0 after the first 15 minutes; or `Orphan Nodes` failing to return to its T+0 baseline after a scene unload (a rising non-zero floor signals a leak regardless of units).
- **Unity**: Open `Window -> Analysis -> Memory Profiler`. Record `Total Reserved Memory`, `GC Allocated`, and `Object Count` (units as displayed).
  - **Alert**: `GC Allocated` growing monotonically across **3+ consecutive checkpoints**.
- **Unreal Engine**: Run console command `stat memory`. Record `Physical Memory Used` and `Physical Memory Available` (units as displayed).
  - **Alert**: `Physical Memory Used` growth **> 20% over the full soak** compared to T+0.

### Stability & Balance Items per Checkpoint
- **Stability**: No crash/hang/freeze, FPS within `[target FPS]` budget, audio in sync, HUD intact, input responsive without lag spikes.
- **Balance / Fatigue** (`balance` or `all`): core mechanic still rewarding (Y/N), difficulty perception (`too easy / appropriate / too hard`), content exhaustion / "seen this before" moments, peak engagement and frustration notes.

---

## 4. Protocol Document & Verdict Rules

Generate `production/qa/soak-test-[date]-[duration].md` with:
1. Header (`Date`, `Duration`, `Focus`, `Engine`, `Generated by: ags-qa`)
2. `## Pre-Session Setup` (fresh launch, background apps closed, engine memory monitor active, session target, prior known issues)
3. `## Baseline (T+0) — Record Before Playing`
4. `## Checkpoint Log` (repeated per timed checkpoint with Value, Delta from Baseline, Alert?)
5. `## Post-Session Analysis` (Memory Trend delta/hr + estimated time to OOM, Stability Summary, Balance/Fatigue Summary, Issues Found `SOAK-001` with `S1`–`S4`)
6. `## Verdict` and `## Sign-Off` (`test-engineer`, `qa-lead`)

### Verdict Rules
- **`FAIL`**: Confirmed memory leak, crash/hang/stability breach, or severe fun fatigue.
- **`NOT ASSESSED`** *(ranks above both pass values and below `FAIL`)*:
  - Soak ended early before reaching its scheduled checkpoints (`NOT ASSESSED — reached T+[N] of [duration]; checkpoints [list] not reached`).
  - Session crashed for causes unrelated to the soak before target duration.
  - No memory instrumentation was available (`"no leaks detected"` cannot pass if nothing was measured).
  - Protocol document was generated but never executed.
  - *(Note: an actual crash observed at T+20 still triggers `FAIL`, never demoted behind run length.)*
- **`PASS WITH CONCERNS`**: Minor drift or fatigue noted; addressable in Polish.
- **`PASS`**: Full duration completed, zero leaks, stability maintained, fun consistent.

---

## 5. Write & Follow-Up

Confirm writing `production/qa/soak-test-[date]-[duration].md` per `modes.automation`. Never attempt to execute a soak test automatically — humans observe and fill checkpoints. Afterward, file discovered issues under `production/qa/bugs/` (`ags-bugs report`), run `ags-bugs triage sprint`, and re-run `ags-qa smoke-check` if `FAIL`.
