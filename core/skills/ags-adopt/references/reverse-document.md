# Reverse Documentation Reference (`ags-adopt reverse`)

Analyzes existing source code or prototypes and produces design or architecture documentation with explicit intent clarification and provenance markers.

## Phase 1: Parse Arguments & Resolve Tier

Invocation: `ags-adopt reverse <design|architecture|concept> <path>`
- `design`: generate GDD (or game brief at `minimal`) from gameplay/UI code.
- `architecture`: generate ADR/architecture doc from core/AI/networking code.
- `concept`: generate concept doc from `prototypes/<name>/`.

Resolve `modes.workflow` (plus `workflow_overrides.system_overrides.<system>` for `<path>`) and code root (`src/` Godot, `Assets/` Unity, `Source/` Unreal). **If `<path>` targets game code and the code root is unresolved, report `NOT ASSESSED — code root unresolved` and stop.**

## Phase 2: Analyze Implementation

- **`design`**: mechanics, rules, formulas, gameplay constants (damage, cooldowns, ranges), state machines, edge cases handled in code, system interactions.
- **`architecture`**: structural patterns (ECS, signals, service locator, observer), serialization/threading decisions, coupling, performance trade-offs.
- **`concept`**: core mechanic, emergent behavior, what worked vs failed, technical feasibility insights, player fantasy/feel.

## Phase 3: Clarify Intent (Never Just Describe Code)

Ask targeted **"why"** questions:
- Design: Is this resource depletion for pacing or strategic scarcity? Core pillar or support? Is this exponential curve intentional or needing rebalance?
- Architecture: Why was this pattern chosen (testability, decoupling, legacy)? Are manual allocations a performance constraint or accidental?
- Concept: Is the observed playstyle/exploit intended as a pillar or a bug?

## Phase 3b: Sufficiency Check (Mandatory Stop Gate)

Count what Phase 2 actually observed on disk:
- **Mechanics**: named behaviors with observable rules (not stubs/empty classes)
- **Formulas**: expressions computing gameplay values from inputs
- **Tuning values**: constants with active use sites

**If all three counts are zero OR `<path>` holds fewer than ~20 lines of non-boilerplate code, STOP and emit `NOT ASSESSED`:**
> "`[path]` lacks sufficient implementation to reverse-document (Found: [N] mechanics, [N] formulas, [N] tuning values). Reverse-documentation infers from behavior; if the design exists in your head, run `ags-gdd design [name]` instead."

For partial implementations (e.g., mechanics present, no formulas), write `none found in the source` under empty headings — **never invent values or rules from genre defaults**.

## Phase 4: Present Findings & Resolve Intent Gaps

Display discovered `MECHANICS IMPLEMENTED`, `FORMULAS DISCOVERED` (or `none found in the source`), and `UNCLEAR INTENT AREAS`. Wait for user clarification. Any unanswered intent questions MUST be carried into the document marked **`INTENT UNKNOWN — inferred from implementation, not confirmed`** — never present inferred intent as confirmed design.

## Phase 5: Draft with Required Provenance Stamp

Select template and output path by type and effective tier:

| Type | Template | Output Path |
|---|---|---|
| `design` (`full`) | `.ags/templates/design-doc-from-implementation.md` | `design/gdd/[system-name].md` (8 sections) |
| `design` (`standard`) | `.ags/templates/design-doc-from-implementation.md` | `design/gdd/[system-name].md` (5 required + conditional numeric Formulas; skip Player Fantasy & Tuning Knobs) |
| `design` (`minimal`) | `.ags/templates/game-brief.md` | `design/game-brief.md` (whole game) or `design/[system-name]-brief.md` (single system) |
| `architecture` | `.ags/templates/architecture-doc-from-code.md` | `docs/architecture/[decision-name].md` |
| `concept` | `.ags/templates/concept-doc-from-prototype.md` | `prototypes/[name]/CONCEPT.md` or `design/concepts/[name].md` |

**Mandatory Provenance Header** (placed immediately under the title alongside frontmatter `status: reverse-documented`, `source: <path>`, `date: <YYYY-MM-DD>`, `verified-by: <user>`):

```markdown
> **Reverse-documented from implementation** — generated by `ags-adopt reverse`
> from `[path]` on `[date]`, at commit `[short-sha]`.
> This records what the code **does**; intent marked `INTENT UNKNOWN` below was
> inferred, not confirmed by the author. Where this document and the code
> disagree, do not assume the document is the requirement.
```

Preserve this banner across revisions unless the author explicitly confirms intent and removes it.

## Phase 6–8: Confirm, Write & Follow Up

Present key sections, explicit additions, and incomplete/inferred gaps; confirm output path per `modes.automation` (`collaborative` always asks; `guided` asks for new files and applies diffs for updates; `autonomous` writes and logs).

Recommend follow-ups after writing:
- Balance outliers flagged -> `ags-design-review balance`
- Architecture gaps -> `ags-architect` (new ADR)
- Missing edge cases -> update GDD / story backlog
