# Bug Triage & Trend Analysis (`ags-bugs triage`)

Processes open bug reports into a sprint-assigned priority list, distinguishes objective severity from team priority, surfaces systemic quality patterns, and tracks backlog trends.

**Output:** `production/qa/bug-triage-[date].md`

---

## 1. Parse Modes

- **`sprint`**: triage against active sprint capacity; assign fixable P1/P2 bugs to sprint or flag overflow.
- **`full`**: triage all open bugs (`P1` -> current sprint, `P2` -> next sprint, `P3+` -> backlog).
- **`trend`**: read-only trend report without sprint assignment or file writes unless requested.
- Blank: run `sprint` if an active sprint exists, else `full`.

---

## 2. Load Bug Backlog & Context

1. **Discover bug files** (priority order):
   - `production/qa/bugs/*.md` (preferred)
   - `production/qa/bugs.md` (consolidated fallback)
   - `production/qa/qa-plan-*.md` `"Bugs Found"` table (last resort)
   - **If zero bug files exist**: STOP and emit **`NOT ASSESSED — no bug files found`** in `production/qa/bugs/`. Do not output a clean zero-bug triage report.
2. **In `trend` mode, skip full bug body reads**: extract bolded header fields (`**Severity**`, `**Priority**`, `**Status**`, `**System**`, `**Category**`, `**Reported**`) and check story statuses (`Status: Complete`) directly for regression detection. Read full bug bodies only for `sprint`/`full` priority re-evaluation.
3. **Load sprint context**: read latest `production/sprints/` file for sprint name, stories in scope, and capacity constraints (`"No sprint plan found — assigning to backlog only."` if absent). Check `.ags/rules/test-standards.md` if needed.

---

## 3. Classify, Assign & Check Systemic Deviations

### Severity (Objective Impact)
| Severity | Definition |
|---|---|
| **S1 — Critical** | Crash, data loss, or complete feature failure; cannot proceed |
| **S2 — High** *(Major)* | Major feature broken but game stays playable; significant wrong behavior |
| **S3 — Medium** *(Minor)* | Feature degraded with workaround available; minor wrong behavior |
| **S4 — Low** *(Trivial)* | Visual glitch, cosmetic issue, typo; no gameplay impact |

### Priority (Team Urgency)
| Priority | Definition |
|---|---|
| **P1 — Fix this sprint** | Blocks QA, blocks release, or regression from last sprint |
| **P2 — Fix soon** | Resolve before next major milestone |
| **P3 — Backlog** | Worth fixing, no active blocking impact |
| **P4 — Won't fix / Deferred** | Accepted risk or out of current scope *(never emit `P4-Wishlist`)* |

### Sprint Assignment & Guardrails
- **Severity is objective; priority is a team decision** — present reclassifications as recommendations.
- **Never auto-assign past sprint capacity**: if capacity is full in `sprint` mode, flag `Priority overflow — consider pulling from sprint` and let the sprint owner decide.
- **Never mark bugs `P4 — Won't Fix` or `Closed` without explicit user approval**: surface `P4` candidates and ask `"Are these acceptable as Won't Fix?"`

### Systemic Deviation Checks
- **3+ bugs in the same system in one sprint** -> `"Potential design or implementation quality issue in [system]."`
- **2+ S1/S2 bugs in the same story** -> `"Story may need to be reopened and re-reviewed before shipping."`
- **Bug filed against a `Status: Complete` story** -> `"Regression in completed story — reopen story in sprint tracking."`

---

## 4. Trend Analysis & Report

Compute:
- **Volume**: total open, opened this sprint, closed this sprint, net change (`+N` / `-N`)
- **System hot spots**: system with highest open count and highest `S1`/`S2` ratio
- **Age**: bugs older than 2 sprints, unassigned `S1`/`S2` count (emit warning callout if `> 0`)
- **Regressions**: count of bugs against completed stories

Assemble `production/qa/bug-triage-[date].md` with:
- Header (`Date`, `Mode`, `Generated by: ags-bugs`, `Open bugs processed`, `Sprint in scope`)
- `## Triage Summary` (`Priority | Count | Notes` + `Critical (S1/S2) unfixed count`)
- `## P1 Bugs — Fix This Sprint`
- `## P2 Bugs — Fix Soon`
- `## P3/P4 Bugs — Backlog / Won't Fix`
- `## Systemic Issues Flagged`
- `## Trend Analysis` (informational observations — trend data alone does not block work)
- `## Recommended Actions`

---

## 5. Write & Follow-Up

In `trend` mode, output in conversation without modifying files. In `sprint`/`full` mode, confirm writing `production/qa/bug-triage-[date].md` per `modes.automation` (`COMPLETE` on write, `BLOCKED` if declined).
- Unassigned S1 bugs -> route to `ags-plan` (`sprint-status`) to check capacity.
- Regressions against completed stories -> reopen story and run `ags-qa smoke-check`.
- Zero P1 bugs -> build healthy for QA hand-off.
