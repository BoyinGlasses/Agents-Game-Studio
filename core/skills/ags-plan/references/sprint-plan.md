# Sprint Planning (`ags-plan sprint`)

Creates (`new`), revises (`update`), or reports (`status`) sprint plans and `production/sprint-status.yaml` with `PR-SPRINT` feasibility and QA plan checks.

## Phase 0: Sub-Mode & Conditional `review_mode` Prompt

1. Parse sub-mode: `new`, `update`, or `status`.
2. **`story_granularity` sprint sizing**: `2–4` stories (`coarse`), `6–10` (`balanced`), `15–25` (`fine`).
3. **Conditional unconfigured `review_mode` rule**:
   - Use `review_mode` from `preflight` (unless `--review` was passed).
   - **ONLY** when **no** explicit source was configured (`--review` flag absent, `modes.review_mode` unset in `project.yaml` / `project.local.yaml`, and `production/review-mode.txt` absent) **AND** mode is `new`: prompt the user for sprint review depth (`[A] full`, `[B] lean` recommended, `[C] solo`), AND confirm destination (`project.yaml` persistent vs this sprint only).
   - **Hold the choice in memory — NEVER write config before Phase 1 confirms a story backlog exists under `production/epics/**/story-*.md`.** Only after Phase 1 succeeds and the user confirms persistence, write `modes.review_mode` to `project.yaml` (and `production/review-mode.txt` mirror if applicable).

---

## Phase 1: Gather Context & Backlog Guard

1. **Optional milestone (`production/milestones/`)**: Read if present; normally authored manually from `.ags/templates/milestone-definition.md`. If absent, note `"no milestone defined — planning against the story backlog alone"` and continue — never block or infer a milestone from sprint files.
2. **Previous sprint (`production/sprints/`)**: Read newest sprint for velocity and carryover (`production/sprints/` absent -> Sprint 1).
3. **Story backlog (REQUIRED)**:
   - Search `production/epics/**/story-*.md` and pattern-search `^> \*\*Status\*\*` across them (extract status/title without reading bodies).
   - **If zero story files exist**: STOP immediately and direct to `ags-plan stories` (`ags-plan epics` before it at `standard`/`full`). Never fabricate work items for nonexistent stories.
   - Plan from stories with `Status: Ready`.
4. **Design context**: Scan `design/gdd/` (or `design/game-brief.md` at `minimal` — note sprint planning is optional at `minimal`).
5. **Optional risk register (`production/risk-register/`)**: Read if present (authored from `.ags/templates/risk-register-entry.md`). If absent, state once (`"no risk register — risks assessed from the sprint contents only"`) rather than skipping risk analysis silently.

---

## Phase 2: Generate Output (`new` / `update` / `status`)

- **`new`**: Draft `production/sprints/sprint-[N].md` (using `.ags/templates/sprint-plan.md` layout: `# Sprint [N] — [Start] to [End]`, `## Sprint Goal`, `## Capacity` with 20% buffer, `## Tasks` split into `Must Have`, `Should Have`, `Nice to Have`, `## Carryover from Previous Sprint`, `## Risks`, `## Dependencies on External Factors`, and `## Definition of Done for this Sprint` citing `ags-qa smoke`, `ags-team qa`, `production/qa/qa-plan-sprint-[N].md`). Present draft, but do NOT confirm file writes until Phases 4–5 resolve.
- **`update`**: Read latest sprint plan and `production/sprint-status.yaml`, prompt changes (add/remove/reprioritize/re-estimate), preserve `in-progress`/`done` statuses (only `backlog` and `ready-for-dev` move freely), re-run Phase 4 `PR-SPRINT`, and write markdown + YAML together.
- **`status`**: Emit concise status report (`Progress`, `Completed`, `In Progress`, `Not Started`, `Blocked`, `Burndown Assessment`, `Emerging Risks`).

---

## Phase 3: Prepare `production/sprint-status.yaml`

Hold YAML content in context until Phases 4–5 settle, then write alongside `sprint-[N].md`:

```yaml
# Auto-generated by ags-plan sprint. Updated by ags-dev and ags-verify.
# Status mapping (yaml <-> story file Status):
#   backlog       <-> Not Started
#   ready-for-dev <-> Ready
#   in-progress   <-> In Progress
#   review        <-> In Review
#   done          <-> Complete
#   blocked       <-> Blocked

sprint: [N]
goal: "[sprint goal]"
start: "[YYYY-MM-DD]"
end: "[YYYY-MM-DD]"
generated: "[YYYY-MM-DD]"
updated: "[YYYY-MM-DD]"

stories:
  - id: "[epic-story, e.g. 1-1]"
    name: "[story name]"
    file: "production/epics/[epic-slug]/story-NNN-[slug].md"
    priority: must-have   # must-have | should-have | nice-to-have
    status: ready-for-dev # backlog | ready-for-dev | in-progress | review | done | blocked
    owner: ""
    estimate_days: 0
    blocker: ""
    completed: ""
```

Initialize `Must Have` -> `ready-for-dev`, `Should Have`/`Nice to Have` -> `backlog`. In `update`, preserve unchanged statuses, add new stories, and drop removed ones.

---

## Phase 4: Producer Feasibility Gate (`PR-SPRINT`) & Combined Write

1. Check `review_mode`: `solo` / `lean` -> skip with explicit note (`"PR-SPRINT skipped — Solo/Lean mode."`).
2. `full`: Spawn `producer` pointing to `.ags/gates/pr-sprint.md` (parent does not read the gate file), passing story list, estimates, dependencies, capacity, carryover, and milestone constraints:
   - `UNREALISTIC`: Defer stories and re-present before confirming write.
   - `CONCERNS`: Prompt (`[A] Accept risk` / `[B] Defer Should Have stories` / `[C] Extend sprint`).
3. Confirm combined write of `production/sprints/sprint-[N].md` and `production/sprint-status.yaml` (plus persisted `modes.review_mode` if pending from Phase 0). If stories were added outside original epic scope, remind user to run `ags-arch-review scope [epic]`.

---

## Phase 5: QA Plan Gate (All Modes)

Check for `production/qa/qa-plan-sprint-[N].md` (or QA file referencing Sprint `[N]`):
- **Found**: Print `"QA Plan: [path]"` and proceed.
- **Missing**: Prompt user explicitly:
  - `[A] Run ags-qa plan sprint before implementation (Recommended)`
  - `[B] Skip for now — embed warning note acknowledging Production -> Polish gate risk`

Close with next steps: `ags-qa plan sprint`, `ags-dev readiness [story-file]`, `ags-dev implement [story-file]`, `ags-plan status`, and `ags-arch-review scope [epic]`.
